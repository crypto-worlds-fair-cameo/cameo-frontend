# 시즌 캔버스 1단계 프론트 구현 스펙

- 작성일: 2026-10-07
- 상태: 구현 전 검토용 설계. 이 문서는 구현 완료나 서버 배포 완료를 뜻하지 않는다.
- 기준 계약: [백엔드 프론트 연동 지침](../../../../backend/docs/frontend/season-canvas-phase-one.md)
- 구현 위치: 기존 `/season-canvas`, `src/pages/season-canvas/`
- 목표: 공개 시즌을 조회하고, 서버 로그인 사용자가 시즌을 개설·취소·조기 종료할 수 있다.
- 설계 근거: code-mapper의 기존 코드 조사와 `docs/convention.md`, page-first 아키텍처 지침.

## 1. 범위와 결정

### 포함

1. 공개 시즌 목록, 전체·예약·진행·종료 필터, 이전·다음 페이지 탐색.
2. 시즌 상세 모달과 서버가 반환한 설정·상태·사용자별 권한 표시.
3. 즉시 개설·예약 개설 폼, 입력 검증, 생성 결과 표시.
4. 개설자의 예약 취소·조기 종료와 확인 절차.
5. 로딩·빈 결과·오류·세션 변경·시간 경계 처리.
6. 영어·한국어 번역, 모바일·데스크톱 접근성 및 반응형 검증.

### 제외

일반 사용자 참가, 참가자 목록, 시즌 소켓 연결, 그림 입력·조회, 작품 미리보기, 썸네일, 결제, NFT 발행은 구현하지 않는다. 검색·인기순·내 시즌 필터, 수정·삭제·복원도 API가 없으므로 제공하지 않는다. 목록 일부를 필터링해 전체 내 시즌 목록인 것처럼 표시하지 않는다.

`isParticipant`와 `active`는 그리기 가능 여부가 아니다. 참가·입장·그리기 버튼을 동작 가능한 상태로 만들지 않는다. 화면에 “현재는 시즌 개설과 정보 조회를 지원합니다. 참가와 그리기는 준비 중입니다.”에 해당하는 번역 문구를 표시한다. 샘플 시즌이나 가짜 썸네일로 실제 API 응답을 대체하지 않는다.

### 화면 구성안

기존 페이지 안에서 목록과 로컬 Dialog로 구성한다. 기존 라우트와 메뉴는 유지한다.

| 대안                        | 판단                                                                              |
| --------------------------- | --------------------------------------------------------------------------------- |
| 목록 + 개설·상세 모달       | 채택. 기존 라우트와 Dialog를 활용하고 1단계 범위에 집중한다.                      |
| 개설·상세 독립 라우트       | 공유 URL에는 유리하나 라우팅 변경과 추가 화면이 필요하다. 이번 범위에서 제외한다. |
| 시즌 그리기 화면까지 선구현 | 미제공 계약을 가정하게 되므로 제외한다.                                           |

이 문서의 화면 배치는 기존 공통 UI를 사용하는 기본안이다. 별도 디자인 원본과 픽셀 단위 시각 승인은 확인하지 않았다. 디자인 적용 시 아래 동작·상태·계약은 유지한다.

## 3. 화면과 사용자 흐름

### 목록

- 상단: 페이지 제목, 1단계 지원 범위 안내, “시즌 개설” 버튼.
- 비로그인: 목록·상세는 열람 가능하다. 개설 버튼은 비활성화하고 헤더의 지갑 연결로 로그인하라는 안내를 표시한다. 페이지에서 `app`의 로그인 UI를 import하지 않는다.
- 세션 초기 조회 중: 개설 버튼을 준비 상태로 표시한다. 세션 확인 오류는 익명 상태로 단정하지 않고 재시도 안내를 표시한다.
- 필터: 전체, 예약, 진행, 종료. 전체는 API `status`를 생략한다.
- 카드: 제목, 설명(있는 경우), 상태, 누적 등록 인원/정원, 시작·종료 시각, 크기, 1인당 획 제한, 본인의 개설자·참가자 여부.
- 사용자 UUID를 닉네임이나 지갑 주소처럼 표시하지 않는다. 현재 접속 인원이라는 표현을 사용하지 않는다.
- 카드의 상세 버튼으로 정보 모달을 연다. 썸네일 없이 텍스트 중심으로 구성한다.
- 탐색: 이전, 현재 페이지 번호, 다음. `page === 1`이면 이전 비활성화, `hasNext === false`이면 다음 비활성화. 총 건수·마지막 페이지를 만들지 않는다.
- 목록은 페이지별 교체 방식이다. 무한 스크롤과 페이지 간 이어 붙이기는 사용하지 않는다.
- 최초 로딩은 Skeleton, 정상 빈 결과는 필터별 안내, 최초 조회 실패는 ErrorState와 재시도 버튼을 표시한다.
- 재조회 실패 시 기존 목록을 유지할 수 있으나 “최신 정보를 불러오지 못했습니다”와 재시도를 함께 표시한다. 빈 결과로 치환하지 않는다.

### URL 상태

`/season-canvas?status=active&page=2`처럼 필터와 페이지를 query string에 보관한다. 새 route를 만들지 않는다.

- 기본값: 전체, 1페이지, API limit 20.
- 기본값은 URL에서 생략한다. UI의 전체를 뜻하는 `all`은 서버로 전송하지 않는다.
- 허용하지 않은 상태, 중복 키, 빈 값, 소수·0·음수·앞자리 0 페이지는 기본값으로 정규화하고 `replace`한다.
- 필터 변경은 1페이지로 이동한다. 정상 사용자 탐색은 history에 기록하고 뒤로 가기로 복원한다.
- 페이지가 1보다 큰데 정상 응답이 비어 있으면 1페이지로 한 번 이동하여 조회한다.
- 모달 선택과 폼 입력은 URL에 저장하지 않는다. 새로고침 시 모달은 닫힌다.

### 상세

목록 데이터로 제목을 먼저 보여줄 수 있지만 상세 API를 항상 조회한다. 초기 데이터만으로 관리 버튼을 활성화하지 않는다.

- 제목·설명·상태·크기·획 제한·누적 참가 등록 인원·정원·시작 시각·예정 종료 시각을 표시한다.
- 조기 종료된 경우 실제 종료 `forceEndedAt`과 예정 종료 `endsAt`을 구분한다. 종료 대표 시각은 `forceEndedAt ?? endsAt`이다.
- 취소 상태는 `cancelledAt`을 별도 표시한다.
- `canCancel`, `canEnd`가 참인 동작만 표시한다. 둘 다 거짓이면 관리 버튼을 표시하지 않는다.
- 상세 조회 중·실패·세션 변경 중에는 관리 동작을 실행할 수 없다.
- 404는 “시즌을 찾을 수 없거나 접근할 수 없습니다”로 안내한다. 삭제됐다고 단정하지 않는다.

### 개설

로그인된 사용자가 개설 버튼을 누르면 폼 Dialog를 연다. 초기값은 정원 20, 1000×1000, 1인당 1획, 즉시 시작, 폼을 연 시점으로부터 24시간 뒤 종료다. 제목과 설명은 빈 문자열이다. 종료 시각은 렌더링마다 바꾸지 않는다.

필수 입력은 제목·정원·종료 시각이다. 설명·크기·획 제한과 즉시/예약 전환을 제공한다. 모든 시즌은 무료·공개이며 개설자도 정원에 포함됨을 안내한다.

1. 프론트 검증 후 단일 생성 요청을 보낸다.
2. 요청 중 제출을 막고 버튼에 진행 상태를 표시한다. Dialog 닫기·Escape·바깥 클릭도 막는다.
3. 성공 시 폼을 닫고 서버 응답의 ID를 선택해 상세 모달을 연다. 입력값으로 서버 정규화 결과를 덮어쓰지 않는다.
4. 목록은 전체·1페이지로 이동하고 관련 목록을 무효화하여 다시 조회한다.
5. 검증·업무 오류는 입력을 보존하고 폼 안에 설명한다.
6. 네트워크·timeout·5xx·비 JSON·성공 응답 해석 실패는 생성 성공 여부 불명확 상태로 전환한다. 자동 재전송하지 않는다.
7. 불명확 상태에서 “목록 확인”과 “중복 생성 가능성을 확인하고 다시 시도”를 구분한다. 후자는 별도 확인 후에만 제출을 다시 허용한다. 제목 일치만으로 생성 성공을 확정하지 않는다.

### 취소·조기 종료

- 예약 취소와 진행 중 조기 종료는 각각 별도 문구·요청으로 구성한다.
- 확인창을 열 때 상세를 다시 조회한다. 최신 권한이 없으면 확인 버튼을 비활성화하고 상태 변경을 안내한다.
- 확인창에 대상 제목, 동작 결과, 되돌릴 수 없다는 안내를 표시한다.
- 요청 중 중복 실행과 확인창 닫기를 막는다.
- 성공하면 확인창을 닫고 서버 응답으로 상세 캐시를 교체한 뒤 목록을 갱신한다. 취소 응답은 상세 모달에 유지한다.
- 취소된 시즌은 공개 목록에서 제거된다. 조기 종료된 시즌은 종료 필터에 속한다.
- 충돌 시 상세·목록을 갱신하고 사용자가 다시 판단하도록 한다. 취소를 종료로 자동 변경하지 않는다.

## 4. 입력 계약과 변환

| 필드                 | UI·전송 규칙                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `title`              | trim 후 Unicode code point 1~50자. `Array.from(value.trim()).length`로 검사한다.                                               |
| `description`        | trim 후 최대 100자. 빈 값은 생략한다. `null`을 보내지 않는다.                                                                  |
| `width`, `height`    | 각각 정수 500~10000. 초기 1000. 비어 있으면 오류로 표시하며 숫자로 전송한다.                                                   |
| `capacity`           | 정수 2~100. 개설자를 포함한 누적 참가 등록 정원이다.                                                                           |
| `strokeLimitPerUser` | 제한 모드 정수 1~10, 무제한 모드 `null`. UI 기본 1을 명시적으로 보낸다. 계약상 생략의 기본값도 1이며 `null`과 혼동하지 않는다. |
| `startsAt`           | 즉시는 생략. 예약은 유효한 미래 시각, 서버 현재부터 최대 30일.                                                                 |
| `endsAt`             | 필수. 시작부터 1시간~30×24시간. 예약 종료 자체를 현재부터 30일로 제한하지 않는다.                                              |

빈 문자열을 먼저 검사한 뒤 숫자로 변환한다. `Number('')`를 허용하지 않으며 정수 여부와 유한성을 확인한다. 무제한에 `?? 1`을 적용하지 않는다. 허용 필드만 직렬화하며 fee, visibility, creatorId 등을 보내지 않는다.

시간 입력은 브라우저의 로컬 시간대를 사용하고 시간대 이름을 폼에 표시한다. 임의 시간대 선택기는 추가하지 않는다. `datetime-local` 값을 파싱하고 유효성을 확인한 뒤 `toISOString()`으로 전송한다. DST 등으로 입력 시각이 자동 보정되면 입력값과 변환 후 로컬 시각을 비교해 수정 안내를 표시한다.

즉시 개설은 제출 시점 기준 남은 기간이 61분 이상이 되도록 프론트에서 여유를 둔다. 이는 서버의 최소 1시간 규칙을 안전하게 사용하기 위한 UI 정책이다. 최대 30일과 예약 시각은 클라이언트에서 사전 검사하되, 시계 오차·통신 지연에 대한 최종 판단은 서버 오류를 따른다. 즉시 시작 시각을 클라이언트에서 만들어 보내지 않는다.

## 5. API와 타입

정식 타입과 오류 목록은 대상 서버의 `/docs` 및 `/docs-json`의 Seasons 계약을 구현 착수 시 대조한다. 이 문서는 로컬 백엔드 지침에 기반하며 배포된 Swagger를 확인한 결과가 아니다.

| 요청 함수                                      | HTTP                       | 반환         |
| ---------------------------------------------- | -------------------------- | ------------ |
| `listSeasons({ status, page, limit }, signal)` | `GET /seasons`             | `SeasonPage` |
| `getSeason(id, signal)`                        | `GET /seasons/:id`         | `Season`     |
| `createSeason(input)`                          | `POST /seasons`            | `Season`     |
| `cancelSeason(id)`                             | `POST /seasons/:id/cancel` | `Season`     |
| `endSeason(id)`                                | `POST /seasons/:id/end`    | `Season`     |

모든 요청은 기존 Axios 인스턴스에 `withCredentials: true`를 지정한다. 조회는 React Query의 AbortSignal을 전달한다. 생성·취소·종료는 `retry: false`, 조회도 초기 구현은 `retry: false`로 두고 명시적 재시도를 제공한다. 취소·종료에는 본문이 없다.

- `SeasonStatus`: `scheduled | active | ended | cancelled`.
- 목록 필터: `scheduled | active | ended | undefined`.
- `Season`: `id`, `creatorId`, `title`, `description`, `width`, `height`, `strokeLimitPerUser`, `capacity`, `participantCount`, `startsAt`, `endsAt`, `cancelledAt`, `forceEndedAt`, `createdAt`, `status`, `isParticipant`, `isCreator`, `canCancel`, `canEnd`.
- `description`, `strokeLimitPerUser`, `cancelledAt`, `forceEndedAt`는 nullable이다. 날짜는 문자열로 보관한다.
- `SeasonPage`: `{ items: Season[], page: number, limit: number, hasNext: boolean }`.
- 성공 envelope의 `success === true`와 사용에 필요한 data 형태를 확인하고 `data`만 반환한다. 2xx라도 HTML·잘못된 envelope면 성공 처리하지 않는다.
- 업무 오류는 `{ statusCode, success: false, code, message, traceId? }`를 해석한다. 네트워크·전송 취소·잘못된 응답은 별도 유형이다.
- Bearer 토큰·지갑 주소 인증, Cookie·Origin 헤더 수동 조립은 사용하지 않는다.

## 6. 서버 상태·세션·캐시 수명주기

### 상태 소유권

| 상태                        | 소유자                            |
| --------------------------- | --------------------------------- |
| 목록·상세·서버 권한         | React Query의 시즌 query          |
| 로그인 사용자               | 기존 `entities/session` query     |
| 필터·페이지                 | URL query와 페이지 모델           |
| 입력·필드 오류·선택 ID·모달 | 페이지 모델의 로컬 상태           |
| 네트워크 진행·오류          | query/mutation + 표시용 오류 분류 |

서버 응답을 Zustand나 로컬 state에 복사하지 않는다. 생성·취소·종료 응답도 상세 query 캐시에 기록한다. UI 상태에는 선택한 ID만 둔다.

### 세션 경계

세션 키는 기존 메인 캔버스 패턴을 따른다: 익명은 `guest`, 로그인은 사용자 ID와 `session.absoluteExpiresAt`의 조합이다. `expiresAt`은 세션 활동으로 바뀔 수 있으므로 세션 식별자로 사용하지 않는다.

- query key: `['season-canvas', sessionKey, 'list', statusOrAll, page, 20]`, `['season-canvas', sessionKey, 'detail', id]`.
- 세션이 미확정이거나 세션 조회가 오류 상태이면 시즌 요청을 시작하지 않고 확인·재시도 UI를 표시한다. 익명으로 확정되면 공개 조회를 시작한다.
- `useIsMutating({ mutationKey: sessionMutationKey }) > 0`이면 시즌 조회와 쓰기를 중지하고 기존 관리 권한을 숨긴다.
- 세션 변경 mutation 시작 시 진행 중 시즌 조회를 취소하고 로컬 epoch를 증가시켜 기존 쓰기 응답의 UI 반영을 차단한다. 닉네임 변경도 같은 key를 사용하므로 이 기간에는 보수적으로 중지한다.
- 안정된 세션 키가 바뀌면 이전 세션 query를 취소·제거하고 개설·상세·확인 모달과 입력·오류를 초기화한다.
- 세션 변경이 끝나면 현재 세션의 목록·선택 상세를 반드시 재조회한다. 같은 사용자나 실패한 로그인으로 세션 키가 같아도 재조회한다.
- 페이지 진입 때 현재 세션의 캐시를 최신 조회로 확인한다. 계정이 다른 캐시를 placeholder로 사용하지 않는다.
- 각 mutation은 요청 당시 `{ sessionKey, epoch }`를 캡처한다. 응답 시 현재 값과 일치하고 페이지 소유자가 살아 있을 때만 캐시·모달·toast를 갱신한다. 키 비교는 오래된 closure 대신 최신 ref를 사용한다.
- 페이지 unmount 시 epoch를 폐기한다. 늦은 응답이 모달을 다시 열거나 다른 계정 캐시를 덮지 않아야 한다.
- 요청 취소나 응답 무시는 서버의 쓰기 취소를 보장하지 않는다. 자동 재요청을 하지 않는다.

이 정책은 페이지 내부에서 구현한다. `app`의 인증 mutation이 페이지 내부를 import하거나 전역 queryClient에서 페이지별 정책을 알게 만들지 않는다.

### 갱신

- 목록·상세는 staleTime 30초, 창 포커스 복귀 시 재조회한다.
- 페이지가 보이는 동안 30초 간격으로 목록과 열린 상세를 재조회한다. 숨겨진 탭에서는 polling하지 않는다.
- 열린 상세의 시작·종료 경계 도달 시 즉시 해당 상세와 목록을 갱신한다. 서버 상태를 로컬 타이머로 확정하지 않는다.
- 경계 타이머는 다음 가까운 경계만 예약하고 긴 지연은 최대 24시간 단위로 나누어 계산한다. 재조회 후 같은 경계로 무한 요청하지 않으며 서버 상태가 늦으면 정기 재조회로 확인한다.
- 성공한 변경은 상세 응답을 캐시에 기록하고 현재 세션의 모든 목록 필터를 invalidate한다.
- 취소 성공 직후에는 응답 상세를 유지한다. 이후 동일 개설자 세션으로 상세를 재조회할 수 있으나 익명으로 재요청하지 않는다.
- 관리 전 상세 갱신 실패 시 오래된 권한으로 쓰기를 진행하지 않는다.

## 8. 파일 구성과 책임

새 파일은 아래 책임이 필요할 때 생성한다. 단순 전달 wrapper나 빈 폴더를 추가하지 않는다.

```text
src/pages/season-canvas/
  SeasonCanvasPage.tsx                # 화면 블록과 모델 연결
  api/
    seasons.types.ts                 # 요청·응답 DTO와 오류 타입
    seasons.api.ts                   # HTTP, envelope 해석, AbortSignal
    seasons.queries.ts               # query key, 조회, polling 정책
    seasons.mutations.ts             # 변경 요청과 scope가 유효한 캐시 갱신
  model/
    useSeasonList.ts                 # URL 조건, 목록 상태, 페이지 이동
    useSeasonSessionScope.ts         # 세션 키, epoch, 요청 수명과 정리
    useSeasonCreate.ts               # 입력 draft, 검증, 중복·불명확 제출 처리
    useSeasonDetail.ts               # 선택 ID, 상세와 경계 갱신, 관리 확인
  lib/
    seasonForm.ts                    # 숫자·문자·시간 검증 및 요청 변환
    seasonSearchParams.ts            # URL 파싱과 정규화
    seasonErrors.ts                  # 오류 코드별 표시 키와 유형 분류
  ui/
    SeasonList.tsx                   # 목록·빈 결과·이전/다음
    SeasonCard.tsx                   # 목록 항목
    SeasonStatusBadge.tsx            # 4가지 상태 표시
    SeasonCreateDialog.tsx           # 개설 폼과 결과 불명확 안내
    SeasonDetailDialog.tsx           # 상세와 관리 ConfirmDialog 조합
    season-canvas.css                # 페이지 전용 레이아웃
  config/locales/
    en.json
    ko.json
```

기존 파일 변경은 `SeasonCanvasPage.tsx`와 `src/app/i18n/config.ts`가 기본이다. 테스트는 대상 구현 옆에 둔다. 필요한 UI는 `shared`에서 가져오고 세션은 `@/entities/session` 공개 export를 사용한다. 다른 페이지 내부나 헤더 인증 구현을 import하지 않는다.

`api`는 폼·모달을 조작하지 않는다. mutation의 캐시 처리는 `api`, 모달 전환은 `model`이 소유하며 동일한 scope 유효성 검사를 사용한다. 순수 계산은 `lib`, 번역은 `config/locales`가 소유한다.

## 9. UI 품질과 접근성

- 기존 색상·간격·타이포그래피·버튼 토큰을 사용한다. 전역 스타일과 공통 컴포넌트 API는 변경하지 않는다.
- 모바일 360px·390px, 데스크톱 1280px·1440px에서 잘림과 가로 스크롤이 없어야 한다.
- 모바일 폼은 1열, 넓은 화면은 관련 설정만 2열로 배치한다. 긴 제목·오류·번역을 줄바꿈한다.
- 모달은 뷰포트 안에서 내부 스크롤한다. 제목·설명·필드 label, 오류 연결, 포커스 trap·복귀, 키보드 탐색을 확인한다.
- 처리 중 버튼 비활성화와 로딩 텍스트를 함께 제공한다. 오류는 폼 내 live region으로 전달한다.
- 상태를 색만으로 구분하지 않는다. 상세가 열려도 목록 전체 클릭 영역과 관리 버튼이 중첩되지 않게 한다.
- 날짜는 선택 언어로 포맷하고 시간대를 설명한다. KO/EN 양쪽 문구를 작성하며 초기 영어 정책은 유지한다.

### 실제 브라우저·서버 검증

검증 URL은 Vite가 출력한 개발 서버 origin의 `/season-canvas`다. `npm run dev`로 실행한다. `VITE_API_URL`은 서버 prefix까지 포함하고 Swagger 경로에는 prefix를 붙이지 않는다.

1. 익명 목록·공개 상세와 로그인 후 사용자별 플래그를 확인한다.
2. 즉시·예약 시즌을 각각 생성하고 반환 상태·시작 시각·참가 인원 1을 확인한다.
3. 1획·무제한과 입력 제한을 확인한다.
4. 예약 취소 후 목록 제외·개설자 상세 유지, 다른 사용자 접근 제한을 확인한다.
5. 조기 종료 후 ended·forceEndedAt·원래 endsAt 유지를 확인한다.
6. 계정 전환·동일 계정 재로그인·진행 중 로그아웃에서 이전 권한과 응답이 남지 않는지 확인한다.
7. 열린 시즌 3개 제한·상태 충돌·네트워크 단절·재조회 실패를 확인한다. 단절 시 동일 생성 요청이 자동 재전송되지 않아야 한다.
8. 모바일·데스크톱에서 모달 스크롤·포커스·닫기·버튼·필터·뒤로 가기를 확인한다.
9. 메인 캔버스와 헤더 로그인·닉네임 모달이 기존대로 동작하는지 확인한다.
10. 실제 배포 도메인에서 쿠키·CORS 쓰기 요청을 확인한다. 로컬 proxy 성공만으로 배포 인증을 검증했다고 보고하지 않는다.

실제 생성·취소·종료 검증은 지정된 개발·테스트 서버와 테스트 계정에서 수행한다. 대상 환경이 미지정이면 로컬 자동 검증과 실서버 미검증을 구분해 보고한다. 백엔드가 미배포라면 프론트 코드 구현과 연동 완료를 구분하며 완료로 단정하지 않는다.

## 11. 구현 착수 시 확인할 외부 조건

- 연결할 서버 주소, Seasons 배포·DB 마이그레이션, 실제 Swagger 계약.
- 프론트 Origin 허용과 브라우저 세션 쿠키 전달. 서로 다른 사이트에서는 `credentials`만으로 해결되지 않는다.
- 제공할 디자인 원본이 있는지 여부. 없으면 이 문서의 공통 UI 기본안을 사용한다.

위 조건은 현재 코드의 구현 가능성을 막는 기술적 결함이 아니라 실환경 연동·시각 검증에 필요한 입력이다. 후속 참가·그리기 API 계약은 이번 구현에 필요한 선행 조건이 아니다.
