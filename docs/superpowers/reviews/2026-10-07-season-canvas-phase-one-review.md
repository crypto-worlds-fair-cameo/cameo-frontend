# 시즌 캔버스 1단계 구현 점검

- 기준: [구현 스펙](../specs/2026-10-07-season-canvas-phase-one-design.md)
- 역할: frontend-developer 구현, 주 에이전트 코드·브라우저 검토, reviewer 로직 검토, test-automator 세션 경쟁 테스트 보강.
- 검증 환경: Node 24.21.0, Vite `http://localhost:5174/season-canvas`, Chromium.
- API 검증 방식: 사용자 선택에 따라 브라우저 요청을 가로챈 로컬 테스트 응답. 실제 백엔드 호출·지갑 서명·배포 도메인 검증은 수행하지 않았다.
- 현재 상태: 로컬 테스트 응답 기준 구현과 점검 완료. 실제 API 연동은 별도 검증 대상이다.

## 코드 검토와 반영

| 발견 문제                                               | 반영한 변경                                              |
| ------------------------------------------------------- | -------------------------------------------------------- |
| 빠른 연속 제출이 생성 요청을 두 번 실행할 수 있음       | React 렌더 전에도 작동하는 요청 소유자 ref 잠금          |
| A 상세 권한 확인의 늦은 응답이 B 관리 확인을 열 수 있음 | 선택 ID·세션 토큰·확인 대상 결합                         |
| 이전 상세 GET이 취소·종료 결과를 덮을 수 있음           | 해당 GET 취소 후 scope 재확인과 상세 cache 갱신          |
| 24시간보다 먼 상태 경계 timer가 재예약되지 않음         | 남은 시간을 재계산하는 분할 timer와 정리                 |
| 세션 변경 중 관리 확인 로딩 상태가 남음                 | 세션 초기화에 관리 확인 진행 상태 포함                   |
| 동일 목록에서 불명확 생성 결과 확인 시 최신 요청이 없음 | 현재 세션 목록 invalidate 후 전체·1페이지 이동           |
| 안전한 정수 범위를 넘는 URL page 허용                   | `Number.isSafeInteger` 기반 정규화                       |
| 상세 재열기 시 오래된 cache만 사용할 수 있음            | 상세 mount 시 최신 조회                                  |
| 설명 입력 label 연결, 목록 종료 시각, pager label 누락  | Field 연결과 날짜·접근성 문구 보완                       |
| 상세 닫기 후 포커스가 BODY로 빠짐                       | 개설·상세 진입 버튼으로 복귀, 버튼 제거 시 제목으로 복귀 |

## 브라우저 확인 결과

검증 데이터는 소유자·다른 사용자·익명 상태와 예약·진행·종료 시즌을 포함한다. 테스트 응답은 앱 구현에 포함하지 않았다.

| 흐름                 | 확인한 결과                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| 목록과 상태 필터     | 서버 상태별 목록, 첫 페이지 복귀, 전체 필터의 status 생략                                      |
| 페이지 탐색          | 2페이지 이동, `hasNext` 기반 다음 비활성화, 뒤로 가기 복원                                     |
| 예약 취소 후 빈 목록 | 취소 항목 제외와 정상 빈 결과 안내                                                             |
| 목록 503 오류        | 오류 UI, 명시적 재시도, 정상 목록 복구                                                         |
| 빈 제목              | 잘못된 입력 표시 후 요청 차단                                                                  |
| 즉시 개설            | 제목 trim, startsAt 생략, 무제한 null, 성공 후 서버 결과 상세 표시                             |
| 예약 개설            | 예약 시작·종료 ISO 전송, 기본 1획, scheduled 결과 표시                                         |
| 취소                 | 대상 제목 확인, 본문 없는 POST, cancelledAt 표시와 상세 유지                                   |
| 조기 종료            | 본문 없는 POST, 실제 종료와 예정 종료의 별도 표시                                              |
| 생성 503             | 결과 불명확 안내·traceId, 재제출 비활성화, 자동 요청 증가 없음                                 |
| 불명확 생성 재시도   | 중복 위험 확인 후 제출 허용, 이후 입력 오류에서 값 보존                                        |
| 로그아웃             | 개설 비활성화, 개설자·참가자 표시 제거, 익명 상세의 관리 동작 제거                             |
| 개설 모달 반응형     | 360·390·1280·1440px에서 뷰포트 내부 배치와 내부 스크롤                                         |
| 상세 로딩·404·503    | 로딩 표시, 접근 불가 안내, 재시도 복구, 오래된 상세의 관리 버튼 비활성화                       |
| 취소 상태 충돌       | 최신 상세 갱신, 자동 조기 종료 요청 없음, 사용자가 새 동작 선택                                |
| 키보드와 포커스      | Tab 모달 내부 순환, 닫기 후 진입 버튼 복귀, 제출 중 Escape 차단, 생성 성공 후 상세 내부 포커스 |
| 목록·상세 반응형     | 360·390·1280·1440px에서 가로 넘침 없음, 상세 모달 뷰포트 내부 배치                             |
| 한국어               | 목록·카드·개설 모달의 한국어 표시                                                              |
| 메인 캔버스          | 툴바·팔레트·캔버스 표시와 연습 모드 전환                                                       |

## 자동 검증

- `npm test`: 27개 파일, 178개 테스트 통과.
- `npm run format:check`, `npm run lint`, `npm run build`, `git diff --check`: 통과.
- 세션 변경·동일 사용자 재로그인·늦은 응답 격리, 연속 생성 방지, 관리 대상 변경, 상세 GET과 mutation 경쟁, 48시간 상태 경계를 회귀 테스트로 확인했다.
- 실제 QueryClient 기반 테스트에서 30초 조회, 숨김 상태 조회 중단, 포커스 복귀 조회를 확인했다. 브라우저 자동화에서는 다른 탭을 선택해도 visibilityState가 visible로 유지되어 숨김 동작을 직접 검증하지 못했다.
- 기존 `public/fonts/fonts.css`의 포맷 오류는 변경 전 HEAD에서도 재현됐다. 사용자 승인에 따라 포맷만 정리했으며, 공백을 제외한 내용이 동일함을 확인했다.

## 검증 한계

- 실제 서버의 Seasons 배포·DB 마이그레이션·Swagger 일치 여부, CORS와 실제 쿠키 전송은 별도 연동 검증이 필요하다.
- 메인 캔버스 소켓·시즌 참가·그리기·결제·NFT는 이번 구현 범위가 아니다.
- 구현 전에도 브라우저에 React script-tag 경고와 favicon 404가 있었다. 시즌 기능의 새 오류와 구분한다.
